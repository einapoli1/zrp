## Critical Issues (Must Fix)

### 1. CardTitle Uses Non-Semantic `<div>` Instead of Headings
**Impact**: Screen readers can't build document outline  
**WCAG**: 1.3.1 Info and Relationships (Level A)  
**Location**: `src/components/ui/card.tsx`

**Current**:
```tsx
const CardTitle = React.forwardRef<HTMLDivElement, ...>(({ className, ...props }, ref) => (
  <div className={cn("font-semibold leading-none tracking-tight", className)} {...props} />
))
```

**Fix**: Change to `<h2>` by default with option to override:
```tsx
interface CardTitleProps extends React.HTMLAttributes<HTMLHeadingElement> {
  asChild?: boolean;
  level?: 2 | 3 | 4 | 5 | 6;
}

const CardTitle = React.forwardRef<HTMLHeadingElement, CardTitleProps>(
  ({ className, level = 2, ...props }, ref) => {
    const Heading = `h${level}` as const;
    return (
      <Heading
        ref={ref}
        className={cn("font-semibold leading-none tracking-tight", className)}
        {...props}
      />
    );
  }
);
```

**Affected Pages**: All (Dashboard, Parts, ECOs, WorkOrders)

### 2. Missing `aria-label` on Icon-Only Buttons
**Impact**: Screen reader users can't identify button purpose  
**WCAG**: 4.1.2 Name, Role, Value (Level A)

#### Parts.tsx - Line ~279
**Current**:
```tsx
<Button type="button" variant="outline" size="icon" 
  onClick={() => setNewCatDialogOpen(true)} title="New Category">
  <Plus className="h-4 w-4" />
</Button>
```

**Fix**:
```tsx
<Button type="button" variant="outline" size="icon" 
  onClick={() => setNewCatDialogOpen(true)} 
  aria-label="Add new category"
  title="Add new category">
  <Plus className="h-4 w-4" aria-hidden="true" />
</Button>
```

#### Parts.tsx - Line ~358
**Current**:
```tsx
<Button variant="outline" onClick={handleReset}>
  <RotateCcw className="h-4 w-4" />
</Button>
```

**Fix**:
```tsx
<Button variant="outline" onClick={handleReset} aria-label="Reset filters">
  <RotateCcw className="h-4 w-4" aria-hidden="true" />
</Button>
```

### 3. Export Dropdown Buttons Missing Explicit Labels
**Impact**: Screen readers may not announce dropdown purpose clearly  
**WCAG**: 4.1.2 Name, Role, Value (Level A)  
**Location**: Parts.tsx, ECOs.tsx, WorkOrders.tsx

**Current** (all pages):
```tsx
<DropdownMenuTrigger asChild>
  <Button variant="outline" className="min-h-[44px] flex-1 sm:flex-none">
    <Download className="h-4 w-4 sm:mr-2" />
    <span className="hidden sm:inline">Export</span>
  </Button>
</DropdownMenuTrigger>
```

**Fix**: Add `aria-label` for screen readers when text is hidden on mobile:
```tsx
<DropdownMenuTrigger asChild>
  <Button variant="outline" className="min-h-[44px] flex-1 sm:flex-none" aria-label="Export data">
    <Download className="h-4 w-4 sm:mr-2" aria-hidden="true" />
    <span className="hidden sm:inline" aria-hidden="true">Export</span>
    <span className="sr-only">Export data</span>
  </Button>
</DropdownMenuTrigger>
```

### 4. Table Missing `aria-label` and `<caption>`
**Impact**: Screen reader users don't know what table contains  
**WCAG**: 2.4.6 Headings and Labels (Level AA)  
**Location**: Parts.tsx, WorkOrders.tsx

#### Parts.tsx - Line ~620
**Current**:
```tsx
<ConfigurableTable<PartWithFields>
  tableName="parts"
  columns={partsColumns}
  data={displayParts}
  rowKey={(part) => part.ipn}
  // ... missing ariaLabel and caption
/>
```

**Fix**:
```tsx
<ConfigurableTable<PartWithFields>
  tableName="parts"
  columns={partsColumns}
  data={displayParts}
  rowKey={(part) => part.ipn}
  ariaLabel="Parts inventory list"
  caption="List of all parts with IPN, category, description, cost, and stock levels"
  // ... rest of props
/>
```

#### WorkOrders.tsx - Line ~625
**Fix**:
```tsx
<ConfigurableTable<WorkOrder>
  tableName="work-orders"
  columns={woColumns}
  data={workOrders}
  rowKey={(wo) => wo.id}
  ariaLabel="Work orders list"
  caption="List of all work orders with status, priority, and assembly details"
  // ... rest of props
/>
```

### 5. ECOs Table Missing Proper `scope` Attributes
**Impact**: Screen reader users lose context navigating table cells  
**WCAG**: 1.3.1 Info and Relationships (Level A)  
**Location**: ECOs.tsx lines ~353-422

**Current**: Using shadcn TableHead without explicit scope
**Fix**: The shadcn Table component already handles this correctly, but verify implementation:

```tsx
<TableHeader>
  <TableRow>
    <TableHead scope="col">ECO ID</TableHead>
    <TableHead scope="col">Title</TableHead>
    {/* ... etc */}
  </TableRow>
</TableHeader>
```

Check `src/components/ui/table.tsx` to ensure `scope="col"` is passed through.

## Moderate Issues (Should Fix)

### 6. Focus Management on Dialog Open
**Impact**: Keyboard users may lose focus context  
**WCAG**: 2.4.3 Focus Order (Level A)  
**Location**: All pages with dialogs

**Recommendation**: Radix UI Dialog handles this automatically, but verify first focusable element makes sense. Consider adding `autoFocus` to first form field:

```tsx
<Input id="ipn" autoFocus placeholder="Internal Part Number" {...} />
```

### 7. Tab Triggers Should Use `aria-selected`
**Impact**: Screen readers may not announce active tab clearly  
**WCAG**: 4.1.2 Name, Role, Value (Level A)  
**Location**: ECOs.tsx line ~323

**Status**: ✅ Radix UI Tabs component handles this automatically. Verify in browser DevTools.

### 8. Loading States Could Be More Descriptive
**Impact**: Screen reader users may not understand what's loading  
**WCAG**: 1.3.1 Info and Relationships (Level A)  
**Location**: All pages

**Current**:
```tsx
<LoadingState variant="spinner" message="Loading dashboard..." />
```

**Recommendation**: Ensure `LoadingState` component includes:
- `role="status"`
- `aria-live="polite"`
- `aria-busy="true"` on parent container
